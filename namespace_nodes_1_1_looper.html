Nodes::Looper Namespace Reference

Detailed Description

The actions of the loopers' Switches tab, made for footswitches, and the settings that say what they and the transport do.

Mode is the state: it shows what the looper does or is about to do, whatever changed it. Play, Stop, Record and Overdub set it, as setting it by hand does. The other actions say what no value can: "the next thing", "a new layer", "from the start", "this layer". Everything that changes what is heard waits for the next point of the grid, as a change of Mode does; Undo, Redo and Clear act at once, and selecting a layer as well.

The looper (the Engine below) provides, besides the transport's engine:

int looper_passes() const; // passes heard bool looper_muted(int pass) const; void looper_set_muted(int pass, bool muted); void looper_mute(int pass); // toggles void looper_erase(int pass);

What the audio and the MIDI looper share: when they record, overdub, play or stop, sample by sample.

The loopers ask for a mode; the transport waits for the next point of the quantification grid before taking it up, splits the tick there, and hands the looper the spans of the tick with the mode each of them is in. A recording can end on its own after a number of bars, into After record.

The looper (the Engine below) provides:

// Does what transport.actualMode says over [start; start + length[ of // the tick, relative to the tick's first sample. Returns the frames it // did: fewer when it ended a recording itself, with end_recording(), // and the rest is run again once the take is closed. int64_t looper_run(int64_t start, int64_t length);

// Something was recorded or overdubbed since the last call, and the // mode is changing: the take is complete. mode is what was taking in // (Record or Overdub). void looper_close_take( const ossia::token_request& tk, Looper::LoopMode mode, bool ended_by_postaction);

// A recording stopped this many frames after a grid point ends on that // point: what was recorded since is dropped. void looper_trim_recording(int64_t frames);

// An overdub that made the loop longer is stopped: when the playhead is // at most max_frames into the part the loop last grew by, that part is // dropped and the frames the playhead is into it are returned, else -1. int64_t looper_trim_extension(int64_t max_frames);

// StartFrom::InPhase: the loop starts being heard again, at the start of // the span of tk; the looper puts the playhead where the loop would be // had it kept playing since it was made, by the timeline's clock. void looper_rephase(const ossia::token_request& tk);

// What the looper asked request_point() for is done now, on the grid // point the transport takes its requests up on. void looper_point();

// Frames until the playhead reaches the end of the loop, the way it goes, // or -1 when it is not going round a loop. int64_t looper_frames_to_end() const;

// The loop as the period of Quantize's Loop grid, at the start of the // span of tk; see loop_period. Looper::loop_period looper_period(const ossia::token_request& tk) const;

The looper calls transport.taking(mode) whenever it records or overdubs.
