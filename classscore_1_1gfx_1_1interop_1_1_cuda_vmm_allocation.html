◆ exportDmaBufFd()

int score::gfx::interop::CudaVmmAllocation::exportDmaBufFd ( bool  pciBar1 = false) const
noexcept

Export this mapped range as a dma-buf fd via cuMemGetHandleForAddressRange — the cross-API handle type that Vulkan (VK_EXT_external_memory_dma_buf) and GL (EGLImage) can import as an aliasing image, i.e. the CUDA→graphics zero-copy route behind AJA capture-collapse. Unlike exportPosixFd() (opaque fd, which does NOT alias into Vulkan), a dma-buf fd is the spec-defined importable type.

Returns -1 when the device lacks CU_DEVICE_ATTRIBUTE_DMA_BUF_SUPPORTED (the export returns CUDA_ERROR_NOT_SUPPORTED). Where the attribute is set and GPUDirect RDMA is available, the export itself succeeds and DMABufferLock(inRDMA=true) accepts a VMM allocation directly, so the AJA-pin + dma-buf-export chain works. The graphics-side import of the CUDA-exported dma-buf is still unsupported on NVIDIA, though:

  • Vulkan: NVIDIA advertises NO VK_EXT_external_memory_dma_buf (only VK_EXT_image_drm_format_modifier), so the dma-buf fd cannot be imported as a VkImage at all.
  • GL/EGL: EGL_EXT_image_dma_buf_import IS advertised, but importing a CUDA-VMM-exported dma-buf fails with EGL_BAD_ALLOC — NVIDIA's EGL importer rejects a dma-buf carrying no graphics-allocator metadata. The intra-GPU CUDA<->graphics route that DOES work on NVIDIA remains the OPAQUE_FD external-memory path, and DMABufferLock refuses CUDA-imported Vulkan memory — hence the per-frame CUDA bounce copy is retained.
Parameters
pciBar1If true, request a PCIe/BAR1 mapping for the dma-buf (CU_MEM_RANGE_FLAG_DMA_BUF_MAPPING_TYPE_PCIE), needed for third-party DMA peers; default is the plain export. The caller owns the returned fd (close() it, or the Vulkan/GL import dups it). Returns -1 on any failure.

◆ exportPosixFd()

int score::gfx::interop::CudaVmmAllocation::exportPosixFd ( ) const
noexcept

Export the underlying allocation as an OS shareable handle for Vulkan/D3D external-memory import (POSIX fd on Linux). Requires exportable=true at allocate() and a driver exposing cuMemExportToShareableHandle. The caller owns the fd; the Vulkan import consumes it on success. Returns -1 on failure.
