3// A MinGW-flavoured COFF Orc platform.
4//
5// score JIT-links its add-ons (libc++/libunwind, x86_64-w64-windows-gnu) with a
6// hand-built ObjectLinkingLayer (JITLink) and, when the SDK ships compiler-rt's
7// orc_rt, drives the executor through an Orc Platform so we get native TLS, real
8// static-init/atexit scheduling and -- crucially on COFF -- SEH/.pdata exception
9// registration.
10//
11// LLVM's stock COFFPlatform is MSVC-coupled: its constructor unconditionally
12// bootstraps the VC runtime (vcruntime/msvcprt/cmt, via COFFVCRuntimeBootstrapper)
13// and installs MSVC-only CXX aliases (_CxxThrowException -> orc_rt). Those cannot
14// drive a MinGW process (libc++/libunwind, __gxx_personality_seh0). None of that
15// machinery is overridable (private ctor + private members), so we cannot subclass
16// it; instead this is a faithful copy of COFFPlatform's ABI-neutral core with the
17// VC-runtime bootstrap and the _CxxThrowException alias stripped:
18// - __ImageBase header symbol per JITDylib,
19// - __orc_rt_coff_* bootstrap handshake,
20// - per-object __orc_rt_coff_register_object_sections (native .tls, SEH
21// .pdata/.xdata, .CRT$X* initializers),
22// - the ABI-neutral atexit/_onexit -> __orc_rt_coff_*_per_jd aliases.
23// CRT / C++ / EH symbols are resolved from the host process (score.exe is itself
24// MinGW-linked) through the process-symbols JITDylib.
