◆ clock

using Nodes::Looper::looper_view::clock = std::chrono::steady_clock

A running looper sends some thirty messages a second. One that has sent none for longer is paused or gone with the score's stop: what it showed last is not being taken in any more, and a take asked of it may never come, so the last take is the one there is.

◆ m_part_waiting

int Nodes::Looper::looper_view::m_part_waiting {}

A lane's own drag: the files of its passes alone. The last take has them when it has a file per pass and the passes did not change since; else the view asks for them, the lane shows it is preparing them, and the drag starts with the next move once they are there.

◆ m_requests

int Nodes::Looper::looper_view::m_requests {}

While a pass is taken in, the last take lacks it, and it may lack the files Export says: a drag or a Send asks for a take of the loop as it is now, and waits for it. A drag starts with the next move of the mouse once it is there, if the button is still held; else the take is the one the next drag or Send gives.
