Detailed Description

Whether the reader of a processor to UI channel has a wake-up pending.

The writer calls request() after each write and wakes the reader up (with an execution command) only when it returns true; when the wake-up cannot be sent it calls park(), and what it wrote goes with the next wake-up: the next write's, or the one ui_wakeups::retry() sends on a later tick. The reader calls clear() before it reads, so that a write that it misses wakes it up again.
